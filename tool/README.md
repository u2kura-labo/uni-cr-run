# Conflict Record Capture（キャプチャツール）

クリスタルコンフリクトのリザルト画面を撮って、戦績を `matches-日付.jsonl` に保存する Windows 用ツール。
出力はビューア（リポジトリ直下の `index.html`）の「JSONL の形式（v1）」に合わせてある。

## 使い方

1. [Releases](https://github.com/u2kura-labo/uni-cr-run/releases/latest) から `ConflictRecordCapture.exe` をダウンロードして起動する（インストール不要、.NET も不要）
2. 最初に出る設定で、自分のキャラクター名を入れる
3. FF14 を「ボーダーレスウィンドウ（仮想フルスクリーン）」か「ウィンドウモード」にする（フルスクリーンだとボタンが上に出せない）
4. リザルト画面で、クリスタルのボタン（またはホットキー、初期値 `Ctrl+Shift+F12`）を押す
5. 保存フォルダ（初期値：`ドキュメント\Conflict Record`）の `matches-日付.jsonl` をビューアにドロップする

画面に出るのはボタン 2 つ。ドラッグで動かせる（位置は覚える）。押してもゲームからフォーカスを奪わない。

| ボタン | 押すと |
|---|---|
| クリスタル | いまの画面を撮って保存する |
| 歯車 | メニューが開く（設定・停止・終了はここから） |

歯車のメニュー（ボタンを右クリックしても同じものが開く）：

| 項目 | 内容 |
|---|---|
| 自分のジョブ | リザルト画面のアイコンからはまだ読めないので、ここで選ぶ。次に変えるまで使われる |
| 次の試合のマップ | リザルト画面に出ないので、ここで選ぶ。1 試合保存すると「指定しない」に戻る |
| 今すぐ撮る | クリスタルのボタンと同じ |
| 撮影を停止する / 開始する | 止めているあいだは、ボタンもホットキーも効かない（クリスタルが灰色の一時停止の印になる）。終了はしないので、また開始できる |
| スクリーンショットから読み込む… | ゲームのスクショ機能などで撮ってあった画像を、あとから読む |
| 保存フォルダを開く / ビューアを開く / 設定… / 終了 | |

停止・開始・終了は、設定の窓のいちばん上（「撮影中 / 停止中」のところ）からもできる。停止と開始はその場で効くので、保存を押さなくてよい。

## 保存されるもの

```
ドキュメント\Conflict Record\
  matches-2026-09-22.jsonl     1 行 = 1 試合。日付ごとのファイル（撮った日の日付）
  captures\
    cap_20260922_211403.png    撮った画像（設定で保存しないこともできる）
    cap_20260922_211403.ocr.json  うまく読めなかった・要確認のときだけ：OCR の生の結果（読み取りの改善用）
```

- 同じ試合を2回撮っても、中身から作る `id` が同じなので、同じ日のファイルには1回しか書かない（ビューアも中身で重複を飛ばす）
- 各プレイヤーの K / D / A の合計がチーム合計と合わないときは、保存したうえで「要確認」を通知し、JSONL の `warnings` にも書く

## 読み取りの仕組み

ゲームのメモリ・通信・ファイルには触れず、ゲームへのキー入力も送らない。画面に映っているものを撮って読むだけ。

1. `ffxiv_dx11.exe` のウィンドウの中身を撮る（見つからなければ画面全体）。自分のボタンは消してから撮る
2. Windows 標準の文字認識（`Windows.Media.Ocr`、日本語）で読む。小さい文字のため、上限の範囲で 2 倍に拡大してから読む
3. `ResultParser`（`src/UniCrCapture.Core`）で試合データにする
   - 表の見出し（キャラクター名・総与ダメージ量 など）の位置から列を決め、各行の語を列に振り分ける
   - 見出しより上から、勝敗（WIN / LOSE）・進行度・チームの K / D / A、ランクの変化、経過時間を読む
   - 名前の文字の色でチーム（青 = アストラ、オレンジ = アンブラ）、設定の名前（なければ行のハイライト）で自分の行を決める
   - OCR の癖（日本語が1文字ずつに分かれる、数字がカンマで割れる、ー が 一 になる、: が . になる など）を吸収する

まだ読めないもの：他のプレイヤーのジョブ（アイコン）、マップ。

## 開発

```
tool/
  src/UniCrCapture.Core/          読み取りの中心（OS に依存しない。Linux でもテストできる）
  src/UniCrCapture/               Windows アプリ（WPF：ボタン・撮影・OCR・設定）
  tests/UniCrCapture.Core.Tests/  リザルト画面の配置と OCR の癖をまねた作り物で ResultParser をテスト
```

```bash
cd tool
dotnet test                                   # どの OS でも
dotnet build src/UniCrCapture                 # Linux / macOS でもビルドの確認はできる（実行は Windows のみ）
dotnet publish src/UniCrCapture -c Release    # 1 ファイルの exe（win-x64、.NET 同梱）
```

### リリース

`.github/workflows/capture-tool.yml` が、main への push でテストと exe のビルドを行う（Actions の成果物に exe が付く）。
`tool-v0.1.0` のようなタグを push すると、GitHub Releases に exe を公開する。ビューアのダウンロードボタンは `releases/latest` を指しているので、公開すれば自動で最新版になる。

```bash
git tag tool-v0.1.0
git push origin tool-v0.1.0
```
