# Conflict Record Capture（キャプチャツール）

クリスタルコンフリクトのリザルト画面を撮って、戦績を `matches-日付.jsonl` に保存する Windows 用ツール。
出力はビューア（リポジトリ直下の `index.html`）の「JSONL の形式（v1）」に合わせてある。

## 使い方

1. [Releases](https://github.com/u2kura-labo/uni-cr-run/releases/latest) から `ConflictRecordCapture.exe` をダウンロードして起動する（インストール不要、.NET も不要）
2. 最初に出る設定で、自分のキャラクター名を入れる
3. FF14 を「ボーダーレスウィンドウ（仮想フルスクリーン）」か「ウィンドウモード」にする（フルスクリーンだとボタンが上に出せない）
4. リザルト画面で、クリスタルのボタン（またはホットキー、初期値 `Ctrl+Shift+F12`）を押す
5. 保存フォルダ（初期値：`ドキュメント\Conflict Record`）の **`1_戦績_ビューアに入れる`** フォルダにある `matches-日付.jsonl` をビューアにドロップする

画面に出るのはボタン 2 つ。ドラッグで動かせる（位置は覚える）。押してもゲームからフォーカスを奪わない。

| ボタン | 押すと |
|---|---|
| クリスタル | いまの画面を撮って保存する |
| 歯車 | メニューが開く（設定・停止・終了はここから） |

歯車のメニュー（ボタンを右クリックしても同じものが開く）：

| 項目 | 内容 |
|---|---|
| 自分のジョブ | ここで選ぶ。次に変えるまで使われる。選んだジョブのアイコンは自動で覚える |
| 次の試合のマップ | ふだんは時刻から自動で決まる。違うときだけここで上書きする（1 試合保存すると戻る） |
| ジョブのアイコンを読み込む… | ジョブの略称を名前にした画像（`PLD.png` など）のフォルダを読む。覚えたジョブは、他のプレイヤーの行でも分かるようになる |
| 今すぐ撮る | クリスタルのボタンと同じ |
| 撮影を停止する / 開始する | 止めているあいだは、ボタンもホットキーも効かない（クリスタルが灰色の一時停止の印になる）。終了はしないので、また開始できる |
| スクリーンショットから読み込む… | ゲームのスクショ機能などで撮ってあった画像を、あとから読む |
| 保存フォルダを開く / ビューアを開く / 設定… / 終了 | |

設定の窓の右上に、いま動いているアプリのバージョンが出る（入れ替えたかどうかの確認に使う）。

停止・開始・終了は、設定の窓のいちばん上（「撮影中 / 停止中」のところ）からもできる。停止と開始はその場で効くので、保存を押さなくてよい。

## 保存されるもの

```
ドキュメント\Conflict Record\
  1_戦績_ビューアに入れる\
    matches-2026-09-22.jsonl        ← ビューアに入れるのはこれ。1 行 = 1 試合（撮った日の日付ごと）
  2_スクリーンショット\
    cap_20260922_211403.png         撮った画像（設定で保存しないこともできる）
  3_読み取りログ\
    cap_20260922_211403.ocr.json    うまく読めなかった・要確認のときだけ：OCR の生の結果（原因を追うため）
```

- 同じ試合を2回撮っても、中身から作る `id` が同じなので、同じ日のファイルには1回しか書かない（ビューアも中身で重複を飛ばす）
- 各プレイヤーの K / D / A の合計がチーム合計と合わないときは、保存したうえで「要確認」を通知し、JSONL の `warnings` にも書く

## 読み取りの仕組み

ゲームのメモリ・通信・ファイルには触れず、ゲームへのキー入力も送らない。画面に映っているものを撮って読むだけ。

1. `ffxiv_dx11.exe` のウィンドウの中身を撮る（見つからなければ画面全体）。自分のボタンは消してから撮る
2. Windows 標準の文字認識（`Windows.Media.Ocr`、日本語）で画面ぜんぶを読む。小さい文字のため、上限の範囲で 2 倍に拡大してから読む
3. K / D / A の列だけ、もう一度読む（`ResultParser.SmallNumberArea` → `ReplaceArea`）
   - この3列は1桁の数字が離れて並ぶだけなので、画面ぜんぶを1枚で渡すと OCR が丸ごと取りこぼす（10行すべての K と D が落ちた例がある）
   - その帯だけを切り出し、文字の高さが 48 画素くらいになるまで拡大して読み直す。倍率は文字の大きさから決めるので、解像度が変わっても効き目は同じ
   - 拡大は「ドットをそのまま整数倍に並べる」方法で行う。にじませる拡大だと細い数字の線がぼけて、桁が丸ごと落ちる
4. 名前とワールド名の列を、英語だけのモデル（Tesseract、`tessdata/eng.traineddata` を exe に同梱）で読み直す
   - この2列はラテン文字なのに、Windows の文字認識は日本語のモデルしか入っていないことが多く、日本語として読んでしまう
   - そのため `r` が `「`、`l` が `I` になり、短い名前（`I' Bis`）は丸ごと落ちる。あとから直すには限界がある
   - 英語のモデルはそもそも日本語の文字を出さないので、この種の読み違いが起きない。実画像で名前が 8/10 → **10/10** になった
   - 表のマス（1行ぶん）を1つずつ、1行として読ませる。列の端は実際に読めている文字で詰める（ジョブのアイコンや階級を文字として読ませないため）
   - モデルを同梱しているので、使う人は追加のインストールをしなくてよい
5. `ResultParser`（`src/UniCrCapture.Core`）で試合データにする
   - 表の見出し（キャラクター名・総与ダメージ量 など）の位置から列を決め、各行の語を列に振り分ける。両端の列も幅で止めるので、画面の左のチャットや右のパーティ一覧は入らない
   - 見出しより上から、勝敗（WIN / LOSE）・進行度・チームの K / D / A、ランクの変化、経過時間を読む。これらは別々に読むので、チーム合計が読めなくても勝敗は決まる
   - 勝敗は WIN と LOSE の語の位置で決める（両方読めれば、左右の並びだけで決まる）。片方しか読めなければチーム名の位置、どちらも読めなければ進行度の大小を使う
   - 名前の文字の色でチームを決める。どちらの色がどちらの隊かは決め打ちにせず、チーム欄の下地の色から合わせる（実際の画面はアストラが赤・アンブラが青で、逆に決め打ちすると自分の勝敗まで反対に記録される）
   - OCR の癖を吸収する：日本語が1文字ずつに分かれる、数字がカンマで割れる、ー が 一 になる、: が . になる、名前の r が「 になってそこで語が切れる（Kura → `Ku` `「` `a`）、l が I になる（`Salim` → `SaIim`）など
   - 名前は語の間隔でつなぎ直す。FF14 の名前は先頭と `'` `-` の次しか大文字にならないので、全部大文字の語（`KO` → `Ko`）と、小文字のすぐあとの大文字（`HuurindoWindbell` → `Huurindo Windbell`）は読み違いとして直す

## マップとジョブ

どちらもリザルト画面に文字では出ないので、別の方法で決める。

**マップ**は 1 時間ごとに 7 つを順に回るので、試合が始まった時刻（撮った時刻 − 経過時間）から決まる。
撮るまでに間があるぶん計算した時刻は実際より後ろにずれるので、切り替わり直後は「1 つ前かもしれない」と断って確かめる。
保存する前に確認の窓を出し、違っていればその場で選び直せる（設定で出さないようにもできる）。

**ロール**（tank / healer / dps）はジョブのアイコンの下地の色で分かる。
実測で DPS は赤（R81 G48 B47）、ヒーラーは緑（R52 G73 B39）、タンクは青。

**ジョブそのもの**はアイコンの絵柄を見比べて決める（`JobIcons`）。
16×16 の明るさの並びにして比べると、同じジョブは 1.00、違うジョブは最大 0.28 ではっきり分かれる。
見本は2通りで覚える。

- 自分の行から自動で：自分のジョブは設定で分かっているので、撮るたびに覚える
- 画像から：`PLD.png` のようにジョブの略称を名前にした画像のフォルダを、メニューから読み込む

覚えたものは `%APPDATA%\ConflictRecord\jobicons.json` に入る。ジョブが分からない行は、ロールだけ記録する。
アイコンの画像そのものはこのリポジトリには入れていない（ゲームの素材なので、使う人が自分で用意する）。

まだ読めないもの：チーム合計の K / D / A の欄（文字がつぶれていて読めないので、各プレイヤーの合計で代用する）。

## 一括で読み込む

画面を出さずに、フォルダの中の画像をまとめて読み込める。

```
ConflictRecordCapture.exe --import "C:\path\to\images"
```

結果は、そのフォルダの `import-result.txt` に書く（`--quiet` を付けると、終わりのお知らせも出さない）。
設定（自分のキャラクター名・保存フォルダ）は、アプリで設定したものをそのまま使う。

## 使っているもの

- [Tesseract](https://github.com/tesseract-ocr/tesseract)（Apache License 2.0）と、その .NET ラッパー [charlesw/tesseract](https://github.com/charlesw/tesseract)（Apache License 2.0）
- 英語のモデル [`eng.traineddata`](https://github.com/tesseract-ocr/tessdata_fast)（Apache License 2.0）を `src/UniCrCapture/tessdata/` に置いて同梱している

## 開発

```
tool/
  src/UniCrCapture.Core/          読み取りの中心（OS に依存しない。Linux でもテストできる）
  src/UniCrCapture/               Windows アプリ（WPF：ボタン・撮影・OCR・設定）
  tests/UniCrCapture.Core.Tests/  リザルト画面の配置と OCR の癖をまねた作り物で ResultParser をテスト
```

```bash
cd tool
dotnet test                                   # どの OS でも
dotnet build src/UniCrCapture                 # Linux / macOS でもビルドの確認はできる（実行は Windows のみ）
dotnet publish src/UniCrCapture -c Release    # 1 ファイルの exe（win-x64、.NET 同梱）
```

### リリース

`.github/workflows/capture-tool.yml` が、main への push でテストと exe のビルドを行う（Actions の成果物に exe が付く）。
`tool-v0.1.0` のようなタグを push すると、GitHub Releases に exe を公開する。ビューアのダウンロードボタンは `releases/latest` を指しているので、公開すれば自動で最新版になる。

```bash
git tag tool-v0.1.0
git push origin tool-v0.1.0
```
