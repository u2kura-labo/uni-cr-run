# uni-cr-run

FF14 クリスタルコンフリクトの戦績ビューア。

リザルト画面のキャプチャから作った `matches.jsonl` をブラウザにドロップすると、次のものを表示する。

- 勝率の推移、ジョブ別・マップ別・ランク別（試合前のランク）の成績
- 同じジョブの人との比較
- 試合ごとの全員の成績と、パフォーマンス指数・MVP・戦犯候補
- 一緒になったプレイヤーの記録：会った回数、味方のときの勝率（普段の勝率との差）、敵のときの自分の勝率、平均指数

- データは**ブラウザの中（IndexedDB）にだけ**保存する。サーバーには何も送らない
- 2回目以降はページを開くだけで前回の続きが表示される
- 同じファイルをもう一度ドロップしても、取り込み済みの試合（同じ `id`）は飛ばす
- 元データはあくまで手元の `matches.jsonl`。ブラウザのデータを消しても、ドロップし直せば戻る

## パフォーマンス指数

同じジョブの平均を 100 としたときの、その試合の成績。

- K・A・与ダメージ・与ヒール・移送時間は多いほど、D は少ないほど高くなる。各項目の「平均との比」を平均して 100 倍する
- 被ダメージは、タンクだと多くて当然なので使わない
- 平均は、読み込んだ全試合の全プレイヤーから、ジョブごとに出す。記録が 5 人分未満のジョブと、ジョブ不明の人は、全員の平均と比べる
- 1 項目の比は 0.25〜3 倍で打ち切る（K が 0 と 1 の違いのような、小さな数での極端な値を抑えるため）
- 戦犯候補はチーム内で指数が一番低い人、MVP は試合で指数が一番高い人

同じ人かどうかは「キャラクター名＋ワールド」で見分ける。「味方のときの勝率」の普段との差は、自分の全試合の勝率と比べたもの。試合数が少ないうちは偶然の影響が大きいので、並べ替えでは 3 試合以上の人を先に出す。

## 動かし方

ビルドは不要（素の HTML / CSS / JS）。ES モジュールを使っているので、`file://` ではなく HTTP で配信する。

```bash
python3 -m http.server 8000
# → http://localhost:8000/
```

- 「サンプルデータで試す」で `sample/matches.sample.jsonl` を読み込める
- `http://localhost:8000/?demo` で開くと、保存データが空のときだけサンプルを自動で読み込む（見た目の確認用）

静的ファイルだけなので、GitHub Pages / Cloudflare Pages やラボの k3s（nginx など）にそのまま置ける。

## JSONL の形式（v1）

Windows 側のキャプチャツールとの取り決め。**1行 = 1試合**の JSON。

```json
{
  "v": 1,
  "id": "3f9a…",
  "ts": "2026-09-22T21:14:03+09:00",
  "map": "パライストラ",
  "duration": "14:04",
  "rank": { "before": "ダイヤモンド5★★★", "after": "ダイヤモンド4★★☆" },
  "teams": {
    "astra": { "result": "win",  "progress": 50.1, "k": 18, "d": 16, "a": 54 },
    "umbra": { "result": "lose", "progress": 50.0, "k": 16, "d": 18, "a": 49 }
  },
  "players": [
    { "team": "astra", "job": "SGE", "name": "Uni Kura", "world": "Valefor", "tier": "ダイヤモンド",
      "k": 3, "d": 2, "a": 14, "dmg": 1490909, "taken": 1357536, "heal": 2951730, "crystal": "2:38", "self": true }
  ],
  "src": "cap_20260922_211403.png"
}
```

実際の `players` は 10 人分（読みやすさのため上では 1 人だけ）。

### 試合

| キー | 必須 | 内容 |
|---|---|---|
| `v` | ✓ | 形式のバージョン。今は `1` |
| `id` | ✓ | 試合を一意に表す文字列。キャプチャ画像のハッシュを想定。重複の判定に使う |
| `ts` | ✓ | 試合の日時（ISO 8601、タイムゾーン付き）。キャプチャした時刻でよい |
| `teams.astra` / `teams.umbra` | ✓ | `result`（`win` / `lose`）、`k` `d` `a`（チーム合計）、`progress`（進行度 %、任意） |
| `players` | ✓ | 各プレイヤー（下の表） |
| `map` | | マップ名。リザルト画面に出ないので、なければ `null` か省略 |
| `duration` | | 経過時間。`"14:04"` 形式か秒数 |
| `rank` | | `before` / `after`。画面の表記そのまま |
| `src` | | 元画像のファイル名。読み取りを直したときに読み直すため |

### プレイヤー

| キー | 必須 | 内容 |
|---|---|---|
| `team` | ✓ | `astra` / `umbra`（名前の色：青 = アストラ、オレンジ = アンブラ） |
| `k` `d` `a` | ✓ | キル / デス / アシスト |
| `dmg` `taken` `heal` | ✓ | 総与ダメージ量 / 総被ダメージ量 / 総与ヒール量 |
| `self` | 1人だけ ✓ | 自分の行に `true`（画面ではハイライトされている行） |
| `job` | | ジョブの略称（`PLD` `WAR` `DRK` `GNB` `WHM` `SCH` `AST` `SGE` `MNK` `DRG` `NIN` `SAM` `RPR` `VPR` `BRD` `MCH` `DNC` `BLM` `SMN` `RDM` `PCT`）。分からなければ `null` |
| `name` `world` `tier` | | キャラクター名 / ホームワールド / 階級 |
| `crystal` | | 移送時間。`"6:55"` 形式か秒数 |

### 検証

- 形式が壊れている行（JSON として読めない、必須の項目がない、`self` がない・複数あるなど）は取り込まず、行番号つきで表示する
- 各プレイヤーの K / D / A の合計がチーム合計と合わない試合は取り込むが、「要確認」の印を付ける（読み取りミスの検出用）
- 集計（勝率・平均・比較）はすべてビューア側で行う。ツール側は画面から読んだ値だけを書けばよい
