# Conflict Record

FF14 クリスタルコンフリクトの戦績ビューアとキャプチャツール。リポジトリ名は `uni-cr-run`。

## ビューア

ブラウザで動く戦績ビューア（https://u2kura-labo.github.io/uni-cr-run/）。

リザルト画面のキャプチャから作った `matches.jsonl` をブラウザにドロップすると、次のものを表示する。

- 勝率の推移、ジョブ別・マップ別・ランク別（試合前のランク）の成績
- 同じジョブの人との比較
- 試合ごとの全員の成績と、スコア（0〜100）
- 一緒になったプレイヤーの記録：会った回数、スコア（過去の試合の平均）、一緒のときの勝率（普段の勝率との差）、敵のときの自分の勝率

- データは**ブラウザの中（IndexedDB）にだけ**保存する。サーバーには何も送らない
- 2回目以降はページを開くだけで前回の続きが表示される
- 同じ試合は二重に取り込まない（下の「重複の扱い」）
- 元データはあくまで手元の `matches.jsonl`。ブラウザのデータを消しても、ドロップし直せば戻る
- 「エクスポート」で、このブラウザの全試合を 1 つの JSONL（`conflict-record-日付.jsonl`）に書き出せる。別の PC・ブラウザでは、そのファイルを読み込むだけで移せる
- 表示は「概要・分析・試合・プレイヤー」のタブで切り替える。テーマはホワイト・ブラック・ミントの 3 種類

## 個人用です

Conflict Record は、自分の戦績を振り返るための個人用のツールです。他のプレイヤーの名前が入ったデータや、その画面のスクリーンショットを共有しないでください。

- 作成したファイルの各試合には、作成者（自分のキャラクター）の識別子が入る（`o`）

## キャプチャツール（Windows）

`matches-日付.jsonl` は、Windows 用のキャプチャツールで作る。FF14 の画面に小さなボタンを出しておき、リザルト画面で押すと、画面を撮って文字認識で読み、JSONL に追記する。
ダウンロードはビューアの「キャプチャツール（Windows）」ボタンか [Releases](https://github.com/u2kura-labo/uni-cr-run/releases/latest) から。詳しくは [tool/README.md](tool/README.md)。

## スコア

「その試合で、同じ役割の人と比べてどうだったか」を 0〜100 にしたもの（`js/stats.js`）。

- **50 = 同じ役割の平均くらい、100 = めっちゃ強い（平均の 1.4 倍以上）、0 = 弱い（平均の 0.6 倍以下）**
- 同じ試合の、同じ役割（DPS・ヒーラー・タンク。両チーム合わせて）の人の平均と、項目ごとに比べる。同じ試合の中で比べるので、試合の長さや荒れ具合に左右されない
- 項目の重みは役割ごとに変える（`ROLE_WEIGHTS`）。移送時間は強さを表しにくいので使わない。アシスト・キルは少しだけ

  | 項目 | DPS | ヒーラー | タンク |
  |---|---|---|---|
  | 与ダメ | 50% | 25% | 30% |
  | 与ヒール | – | 35% | – |
  | 被ダメ | – | – | 25% |
  | D（少ないほど良い） | 30% | 30% | 25% |
  | K | 10% | – | 10% |
  | A | 10% | 10% | 10% |

- ジョブが分からない人は、役割で分けずに 10 人全員と比べた参考値（`*` 付き）
- スコアをクリックすると、良かった項目・低かった項目（与ダメが平均の何 % か など）を表示する

**プレイヤーのスコア**は、その人と会った試合のスコアの平均（ジョブが分かっていて公平に比べられた試合だけ）。会った回数が多いほど信頼できる（参考：3 試合以下 / 中：4〜9 / 高：10 以上）。

**一緒のときの勝率の「普段との差」**は、試合数が少ないうちは普段の勝率に寄せて補正してから比べる（4 試合分）。3 試合で 3 連勝しても大きな差にはならず、試合数が増えるほど実際の値に近づく。

同じ人かどうかは「キャラクター名＋ワールド」で見分ける。

## 動かし方

ビルドは不要（素の HTML / CSS / JS）。ES モジュールを使っているので、`file://` ではなく HTTP で配信する。

```bash
python3 -m http.server 8000
# → http://localhost:8000/
```

- 「サンプルデータで試す」で `sample/matches.sample.jsonl` を読み込める
- `http://localhost:8000/?demo` で開くと、保存データが空のときだけサンプルを自動で読み込む（見た目の確認用）

静的ファイルだけなので、GitHub Pages / Cloudflare Pages やラボの k3s（nginx など）にそのまま置ける。

## JSONL の形式（v1）

Windows 側のキャプチャツールとの取り決め。**1行 = 1試合**の JSON。

```json
{
  "v": 1,
  "id": "3f9a…",
  "ts": "2026-09-22T21:14:03+09:00",
  "map": "パライストラ",
  "duration": "14:04",
  "rank": { "before": "ダイヤモンド5★★★", "after": "ダイヤモンド4★★☆" },
  "teams": {
    "astra": { "result": "win",  "progress": 50.1, "k": 18, "d": 16, "a": 54 },
    "umbra": { "result": "lose", "progress": 50.0, "k": 16, "d": 18, "a": 49 }
  },
  "players": [
    { "team": "astra", "job": "SGE", "name": "Kinako Mochi", "world": "Tiamat", "tier": "ダイヤモンド",
      "k": 3, "d": 2, "a": 14, "dmg": 1490909, "taken": 1357536, "heal": 2951730, "crystal": "2:38", "self": true }
  ],
  "src": "cap_20260922_211403.png"
}
```

実際の `players` は 10 人分（読みやすさのため上では 1 人だけ）。

### 試合

| キー | 必須 | 内容 |
|---|---|---|
| `v` | ✓ | 形式のバージョン。今は `1` |
| `id` | ✓ | 試合を一意に表す文字列。キャプチャ画像のハッシュを想定。重複の判定に使う |
| `ts` | ✓ | 試合の日時（ISO 8601、タイムゾーン付き）。キャプチャした時刻でよい |
| `teams.astra` / `teams.umbra` | ✓ | `result`（`win` / `lose`）、`k` `d` `a`（チーム合計）、`progress`（進行度 %、任意） |
| `players` | ✓ | 各プレイヤー（下の表） |
| `map` | | マップ名。リザルト画面に出ないので、なければ `null` か省略 |
| `duration` | | 経過時間。`"14:04"` 形式か秒数 |
| `rank` | | `before` / `after`。画面の表記そのまま |
| `src` | | 元画像のファイル名。読み取りを直したときに読み直すため |
| `o` | | 作成者の識別子（`owner=キャラ名@ワールド` を Base64 にしたもの） |
| `warnings` | | ツールが読み取りで気づいた「要確認」の内容 |
| `app` | | 作ったツールとバージョン |

### プレイヤー

| キー | 必須 | 内容 |
|---|---|---|
| `team` | ✓ | `astra` / `umbra`（名前の色：青 = アストラ、オレンジ = アンブラ） |
| `k` `d` `a` | ✓ | キル / デス / アシスト |
| `dmg` `taken` `heal` | ✓ | 総与ダメージ量 / 総被ダメージ量 / 総与ヒール量 |
| `self` | 1人だけ ✓ | 自分の行に `true`（画面ではハイライトされている行） |
| `job` | | ジョブの略称（`PLD` `WAR` `DRK` `GNB` `WHM` `SCH` `AST` `SGE` `MNK` `DRG` `NIN` `SAM` `RPR` `VPR` `BRD` `MCH` `DNC` `BLM` `SMN` `RDM` `PCT`）。分からなければ `null` |
| `name` `world` `tier` | | キャラクター名 / ホームワールド / 階級 |
| `crystal` | | 移送時間。`"6:55"` 形式か秒数 |

### 検証

- 形式が壊れている行（JSON として読めない、必須の項目がない、`self` がない・複数あるなど）は取り込まず、行番号つきで表示する
- 各プレイヤーの K / D / A の合計がチーム合計と合わない試合は取り込むが、「要確認」の印を付ける（読み取りミスの検出用）
- 集計（勝率・平均・比較）はすべてビューア側で行う。ツール側は画面から読んだ値だけを書けばよい

### 重複の扱い

同じ試合を何度読み込んでも、1 試合として数える。次のどれかに当てはまれば同じ試合とみなして飛ばす（`js/dedupe.js`）。

1. `id` が同じ
2. 中身が完全に同じ：10 人のチーム・名前・ワールドと、全員の K / D / A・与ダメ・被ダメ・与ヒールがすべて一致
3. ほぼ同じ：10 人の顔ぶれが同じ、時刻の差が 30 分以内、上の数字の 9 割以上が一致（同じ画面を撮り直して 1〜2 か所読み違えた場合）

同じ 10 人とすぐ再戦した場合は数字が大きく違うので、別の試合として扱われる。ツール側は、同じ画像からは同じ `id` を出すようにしておくとよい（画像のハッシュなど）。
